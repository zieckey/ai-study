# 如何准备 AI 大模型训练数据：Golang 教学示例

本项目用一个可直接运行的 Go 程序，演示大模型训练数据从“原始文本”变成“可训练样本”的基本流程。

大模型并不是把互联网上的原文直接塞进训练程序。真实训练前通常需要经历数据授权、清洗、隐私处理、去重、质量过滤、切分、划分数据集、统计和审计等步骤。这个项目用小规模模拟数据帮助你理解这些核心环节。

> **重要提示**：本项目只使用代码中内置的虚构文本，不下载互联网数据，不处理真实个人数据，也不训练模型。示例里的隐私脱敏和质量判断是教学版本，不能直接当作生产系统使用。

## 运行程序

需要本机安装 Go。进入项目目录后执行：

```bash
go run .
```

也可以执行单元测试：

```bash
go test .
```

程序会按阶段输出：原始数据数量、脱敏样例、去重数量、质量过滤结果、chunk 数量、训练/验证/测试集划分、token 统计和 manifest。

## 数据准备流程

```text
原始文档
  -> 文本清洗
  -> PII 脱敏
  -> 去重
  -> 语言识别
  -> 质量过滤
  -> Tokenize
  -> Chunk 切分
  -> Train / Validation / Test 划分
  -> Token 统计与 Manifest
```

代码位于 [main.go](main.go)。核心结构如下：

```text
main.go
├── RawDocument             原始文档
├── CleanDocument           清洗后的文档
├── Chunk                   可训练文本片段
├── DatasetSplit            训练集/验证集/测试集
├── Manifest                数据处理统计摘要
├── cleanText               清洗空白和控制字符
├── redactPII               替换邮箱、手机号、身份证样式信息
├── deduplicate             基于归一化文本去重
├── detectLanguage          简化语言识别
├── qualityScore            简化质量评分
├── simpleTokenize          简化 token 切分
├── chunkDocument           滑动窗口切分长文本
├── splitDataset            固定随机种子划分数据集
└── buildManifest           生成处理摘要

main_test.go
└── 数据清洗、脱敏、去重、过滤、切分、划分和 manifest 的单元测试
```

## 1. 收集原始数据

训练数据可以来自很多地方，例如网页、书籍、论文、代码、问答、说明文档、人工标注数据等。但真实项目中必须先确认数据来源是否允许用于训练，是否涉及版权、隐私、合规和业务边界。

本示例用 `sampleRawDocuments` 内置了几类模拟文本：

- 正常中文说明文本。
- 正常英文说明文本。
- 中英混合文本。
- 带邮箱、手机号、身份证样式信息的文本。
- 重复文本。
- 过短文本。
- 噪声和广告文本。

这样可以在不依赖外部文件和网络的情况下，观察完整 pipeline。

## 2. 文本清洗

原始文本经常包含多余空格、换行、制表符、不可见控制字符和格式噪声。`cleanText` 做了两件事：

1. 将换行、tab、多空格统一成单个空格。
2. 移除不可见控制字符。

清洗不是为了“改写内容”，而是减少无意义格式差异，让后续去重、过滤和切分更稳定。

## 3. 隐私脱敏

训练数据中可能混入个人信息，例如邮箱、手机号、证件号。真实训练系统必须尽量避免把敏感信息学进模型。

本示例的 `redactPII` 使用 Go 标准库 `regexp` 做简单替换：

```text
alice@example.com      -> [EMAIL]
13800138000            -> [PHONE]
11010119900307123X     -> [ID_CARD]
```

真实生产环境不能只依赖几个正则表达式，通常还需要：

- 更完整的 PII 识别规则和模型。
- 数据分级分类。
- 人工抽检。
- 审计留痕。
- 对高风险领域数据做更严格治理。

## 4. 去重

重复数据会让模型过度记住某些文本，降低数据多样性，也浪费训练算力。`deduplicate` 会先用 `normalizeForDedup` 做归一化：

- 转成小写。
- 移除空白。
- 移除部分标点和符号。

然后用 map 做精确去重。

真实大规模训练数据通常还会做近似去重，例如使用 MinHash、SimHash 或 embedding 相似度，识别“几乎一样”的网页、转载文章和模板化内容。

## 5. 语言识别与质量过滤

并不是所有文本都适合训练。太短、乱码、广告、符号堆砌、语言无法识别的文本通常会被过滤。

本示例使用两个简化函数：

- `detectLanguage`：统计中文字符和英文字母，返回 `zh`、`en`、`mixed` 或 `unknown`。
- `qualityScore`：综合文本长度、文本字符比例、标点比例和重复字符，给出 0 到 1 的质量分。

真实系统中质量过滤会复杂得多，可能包括：

- 语言识别模型。
- 垃圾内容分类器。
- 低质量网页模板识别。
- 毒性、安全、违法违规内容过滤。
- 领域数据白名单或黑名单。

## 6. Tokenize

模型训练时通常不直接处理原始字符串，而是处理 token 序列。token 可以近似理解为模型看到的“最小文本单位”。

本示例的 `simpleTokenize` 是教学版：

- 连续英文和数字作为一个 token。
- 中文按单字切分。
- 常见标点单独成 token。

真实 LLM 通常使用 BPE、SentencePiece、Unigram 等 tokenizer。它们会把高频词、子词、符号、代码片段等切成更适合模型学习的 token。

## 7. Chunk 切分

大模型一次能看到的上下文长度有限。长文档通常要切成多个 chunk，例如每个 chunk 最多 2048、4096 或更多 token。

本示例的 `chunkDocument` 使用滑动窗口：

```text
maxTokens = 24
overlap   = 6
```

overlap 表示相邻 chunk 之间保留一部分重叠 token，避免在切分边界处丢失上下文。

## 8. 划分训练集、验证集和测试集

训练数据通常会拆成三部分：

- **Train**：用于训练模型参数。
- **Validation**：用于调参、选择 checkpoint、观察过拟合。
- **Test**：用于最终评估，不应该参与训练和调参。

本示例使用固定随机种子划分数据，保证每次运行结果可复现。

```text
Train      80%
Validation 10%
Test       10%
```

## 9. Token 统计与 Manifest

训练前需要知道数据的大致规模和分布，例如：

- 有多少原始文档。
- 去掉了多少重复文档。
- 过滤掉了多少低质量文档。
- 最终有多少 chunk。
- 总 token 数是多少。
- 高频 token 是什么。

`buildManifest` 会生成一个 JSON 摘要。manifest 的作用是让数据处理过程可复现、可审计、可对比。当模型效果异常时，团队可以回头检查到底是哪一批数据、哪一条规则或哪个版本发生了变化。

## 大规模训练数据如何准备

这个示例只有几条文本，真实大模型训练数据可能达到 TB/PB 级。规模变大后，核心流程类似，但工程实现会完全不同：

| 教学示例 | 真实大规模系统 |
| --- | --- |
| 内置文本数组 | 对象存储、数据湖、授权数据源 |
| 单机 Go 程序 | Spark、Flink、Beam、MapReduce、Ray 等分布式处理 |
| map 精确去重 | MinHash、SimHash、LSH、分布式去重索引 |
| 简单正则脱敏 | PII 识别模型、规则引擎、合规审核、人工抽检 |
| 简单质量分 | 多模型质量评估、安全分类器、领域过滤器 |
| 简化 tokenizer | BPE、SentencePiece、专用 tokenizer 服务 |
| stdout manifest | 数据版本系统、元数据平台、审计日志、血缘追踪 |

虽然规模和工具不同，但核心问题始终是：

1. 数据从哪里来，是否有权使用？
2. 数据是否干净、重复、低质或有风险？
3. 数据如何变成模型可学习的 token 序列？
4. 训练集、验证集、测试集如何稳定复现？
5. 每次处理的规则、版本和统计能否追溯？

## 本项目边界

本项目主要用于学习，不包含以下能力：

- 不爬取互联网数据。
- 不读取真实用户文件。
- 不训练神经网络模型。
- 不实现工业级 tokenizer。
- 不实现分布式处理。
- 不提供生产级隐私识别、安全审核或版权判断。

你可以先运行本示例理解数据准备的骨架，再继续学习 tokenizer、预训练任务、分布式数据处理和模型训练。
