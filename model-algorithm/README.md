# 算法与模型：Golang 入门示例

本项目通过一个可直接运行的 Go 程序，展示两个基础概念：

1. **算法（Algorithm）**：二分查找。
2. **模型（Model）**：逻辑回归（Logistic Regression），用于输出“违约”的预测概率。

代码位于 [main.go](main.go)。二分查找的规则由程序员明确写出；逻辑回归的权重和偏置则从带标签的样本数据中训练得到。

> **重要提示**：本项目中的贷款数据完全虚构，仅用于算法学习。程序输出的违约概率和类别不构成授信、拒贷、额度、利率或任何金融决策建议。真实金融场景必须经过数据授权、隐私保护、合规审查、公平性评估、模型验证、人工审核和审计留痕。

## 运行程序

需要本机安装 Go。进入项目根目录后执行：

```bash
go run main.go
```

也可以执行单元测试：

```bash
go test .
```

本仓库当前没有 `go.mod`。若你的 Go 环境默认开启模块模式，请使用 GOPATH 兼容模式：

```bash
GO111MODULE=off go test .
GO111MODULE=off go run main.go
```

程序会先打印二分查找结果，再输出逻辑回归模型的训练集/测试集数量、模型参数、每条测试样本的违约概率（PD）、基于阈值的类别预测，以及混淆矩阵和分类指标。

## 程序结构

```text
main.go

```

## 第一部分：算法——二分查找

### 什么是算法

算法是**为解决问题预先定义的一系列明确步骤**。同样的输入、同样的步骤，会得到同样的输出。

程序中的 `binarySearch` 函数在一个**已排序**的整数数组中查找目标值：

```go
func binarySearch(sorted []int, target int) int
```

- `sorted`：必须是从小到大排列的数组。
- `target`：要查找的数字。
- 返回值：找到时返回下标；找不到时返回 `-1`。

Go 的数组下标从 `0` 开始：

```text
下标:  0  1  2  3  4  5  6
数据:  3  8 12 19 24 31 42
```

因此 `24` 位于下标 `4`。

### 代码逐段讲解

```go
left, right := 0, len(sorted)-1
```

`left`、`right` 表示当前搜索区间的左右边界。对 7 个元素的数组，初始搜索区间是 `[0, 6]`。

```go
for left <= right {
    middle := left + (right-left)/2
```

区间尚未为空时，计算中间元素的位置。`left + (right-left)/2` 是常见的稳妥写法，可避免大整数相加可能产生的溢出。

```go
switch {
case sorted[middle] == target:
    return middle
case sorted[middle] < target:
    left = middle + 1
default:
    right = middle - 1
}
```

- 中间值等于目标：立即找到。
- 中间值小于目标：目标只能在右半部分，丢弃左半部分。
- 中间值大于目标：目标只能在左半部分，丢弃右半部分。

查找 `24` 的过程：

| 轮次 | 搜索区间 | 中间下标 | 中间值 | 判断 | 下一步 |
| --- | --- | ---: | ---: | --- | --- |
| 1 | `[0, 6]` | 3 | 19 | `19 < 24` | 搜索 `[4, 6]` |
| 2 | `[4, 6]` | 5 | 31 | `31 > 24` | 搜索 `[4, 4]` |
| 3 | `[4, 4]` | 4 | 24 | `24 == 24` | 返回 `4` |

每一轮大约排除一半元素，因此时间复杂度是 **O(log n)**。二分查找的前提是数组有序；无序数据不能可靠地判断该保留哪一半。

## 第二部分：模型——逻辑回归预测违约概率

### 从连续值预测改为二分类概率

之前的线性回归示例预测一个连续分数，例如 `89.8`。信用风险中，一个常见目标是判断借款人是否可能违约，因此标签是二元的：

```text
0 = 未违约（non-default）
1 = 违约（default）
```

一条样本由多个数值特征和一个标签构成：

```go
type Sample struct {
    Features []float64
    Label    float64
}
```

本示例使用完全虚构的非识别性数据，特征仅用于演示：

| 特征 | 含义 | 示例值 |
| --- | --- | --- |
| `debt-to-income ratio` | 负债收入比 | `0.44`，即 44% |
| `prior late payments` | 历史逾期次数 | `2` |
| `on-time repayment ratio` | 历史按期还款比例 | `0.78`，即 78% |

例如：

```go
Sample{
    Features: []float64{0.44, 2, 0.78},
    Label:    1,
}
```

它表示一条**虚构的教学样本**。真实信用数据必须基于合法授权和严格的数据治理，且不能使用敏感、受保护或不应作为授信依据的信息。

### 为什么不能直接用线性回归预测标签

线性回归可以输出任意实数，例如 `-0.3` 或 `1.6`。这不适合作为概率，因为概率必须在 `[0, 1]` 之间。

逻辑回归先计算一个线性分数：

```text
z = b + w₁x₁ + w₂x₂ + … + wₙxₙ
```

再通过 sigmoid 函数转换为概率：

```text
PD = sigmoid(z) = 1 / (1 + e⁻ᶻ)
```

- `PD`：违约概率（Probability of Default），范围为 `[0, 1]`。
- `x₁ ... xₙ`：输入特征。
- `w₁ ... wₙ`：模型训练获得的权重。
- `b`：偏置（bias）。

当 `z` 很大时，`PD` 接近 `1`；当 `z` 很小时，`PD` 接近 `0`。因此逻辑回归适合输出二分类事件的概率。

### `LogisticModel`：保存参数和标准化规则

```go
type LogisticModel struct {
    Weights []float64
    Bias    float64
    Means   []float64
    Scales  []float64
}
```

模型不仅保存权重和偏置，也保存每个特征的训练集均值、标准差：

- `Weights`：各标准化特征的权重。
- `Bias`：不依赖输入特征的基础分数。
- `Means`：训练集各特征的平均值。
- `Scales`：训练集各特征的标准差。

### 为什么要标准化特征

示例中的三个特征量纲不同：负债收入比约为 `0` 到 `1`，逾期次数是整数，按期还款比例也约为 `0` 到 `1`。如果直接梯度下降，数值较大的特征可能主导更新，使训练变慢或不稳定。

程序使用标准化公式：

```text
x标准化 = (x - 平均值) / 标准差
```

**均值与标准差只能从训练集计算。** 测试集只能使用训练集的 `Means` 和 `Scales` 转换，不能参与统计量计算；否则就会提前泄漏测试集分布信息。

当某个特征在训练集中完全不变时，标准差是 `0`。代码将它标准化为 `0`，避免除以零；这类特征没有区分能力，实际项目通常应被移除或进一步检查。

### `PredictProbability`：计算 PD

```go
func (m LogisticModel) PredictProbability(features []float64) (float64, error)
```

预测步骤：

1. 检查输入特征数量是否与模型权重数量一致。
2. 使用训练时保存的均值和标准差标准化新样本。
3. 计算 `z = b + Σ(wᵢ × xᵢ标准化)`。
4. 调用 `sigmoid(z)`，返回 `[0, 1]` 内的违约概率。

`sigmoid` 对正数和负数使用不同但等价的公式，避免 `math.Exp` 在极端输入下溢出或溢出：

```go
if value >= 0 {
    return 1 / (1 + math.Exp(-value))
}
exp := math.Exp(value)
return exp / (1 + exp)
```

### `PredictClass`：将概率转换为类别

概率不是最终类别。代码以 `0.5` 为教学阈值：

```text
PD ≥ 0.5  → 预测为违约（1）
PD < 0.5  → 预测为未违约（0）
```

```go
func (m LogisticModel) PredictClass(features []float64, threshold float64) (int, error)
```

真实风险管理中，阈值不是任意固定为 `0.5`：它必须在风险偏好、预期损失、审批率、产品政策、合规约束和人工审核机制下审慎确定，且不能以模型阈值绕过任何强制规则。

## 第三部分：用梯度下降训练逻辑回归

### 训练目标

`trainLogisticModel` 通过已知的 `0/1` 标签，让预测概率逐步接近训练样本的真实结果。它接受学习率与迭代次数：

```go
trainLogisticModel(samples, 0.1, 2000)
```

- `0.1`：学习率，每次参数更新的步长。
- `2000`：迭代次数，表示用全部训练样本更新参数 2000 次。

这两个值用于教学。不同数据集需要实验、验证与监控，不能简单照搬。

### 全批量梯度下降

每轮训练都使用全部训练样本：

1. 计算每条样本的预测概率 `p`。
2. 计算误差 `p - label`。
3. 累加各权重和偏置的梯度。
4. 使用平均梯度更新参数：

```text
wᵢ = wᵢ - 学习率 × 平均梯度
b  = b  - 学习率 × 偏置的平均梯度
```

这种方法称为**全批量梯度下降**。代码从全零权重和偏置开始，因而在相同数据、学习率和迭代次数下结果可复现。

训练函数会拒绝以下无效数据：空样本、无特征、特征维度不一致、非 `0/1` 标签、NaN/无穷大特征、非法学习率和非法迭代次数。

## 第四部分：训练集与测试集

### 为什么不能用训练数据评估自己

若模型既看过某些数据，又用这些数据评估好坏，它可能只是“记住”了样本，不能说明面对新数据是否可靠。这是一种常见的数据泄漏问题。

程序先调用：

```go
trainSamples, testSamples, err := splitSamples(samples, 0.8, 42)
```

- `0.8`：80% 样本训练，20% 样本测试。
- `42`：随机种子。相同种子产生相同打乱顺序，使学习输出和测试可复现。

`splitSamples` 会先复制原始切片再打乱复制品，因此不会修改调用方保存的原始样本顺序，并确保训练集、测试集都至少包含一条样本。

```text
全部带 0/1 标签的样本
      │
      ├── 固定种子打乱
      │
      ├── 80% 训练集 ──> 标准化统计 + 梯度下降 ──> LogisticModel
      │
      └── 20% 测试集 ──> PD + 阈值分类 + evaluate ──> 分类指标
```

测试集标签只在最后用于比较预测结果，不能参与训练、均值计算或标准差计算。

## 第五部分：分类指标

逻辑回归先输出概率，再按阈值得到类别。因此不能继续使用 MAE/RMSE 作为主要教学指标，而要查看分类结果。

### 混淆矩阵

在“违约”为正类（`1`）的设定下：

| 结果 | 含义 |
| --- | --- |
| TP（True Positive） | 实际违约，模型也预测违约 |
| TN（True Negative） | 实际未违约，模型也预测未违约 |
| FP（False Positive） | 实际未违约，却预测违约 |
| FN（False Negative） | 实际违约，却预测未违约 |

`evaluate` 函数只使用测试集，统计 TP、TN、FP、FN，然后计算：

```text
Accuracy  = (TP + TN) / 全部样本数
Precision = TP / (TP + FP)
Recall    = TP / (TP + FN)
```

- **Accuracy（准确率）**：整体预测正确的比例。
- **Precision（精确率）**：被预测为违约的人中，实际违约的比例。
- **Recall（召回率）**：实际违约的人中，被模型识别出来的比例。

违约往往是少数事件，因此不能只依赖 Accuracy。例如 99% 样本未违约时，始终预测“未违约”也有 99% 准确率，但 Recall 为 0，不能识别违约风险。

真实项目还应评估 AUC、KS、PR-AUC、概率校准度、分箱坏账率单调性、PSI/CSI、稳定性与公平性。小型合成测试集上的指标不具备统计意义。

## 第六部分：应用案例——金融信用贷款的还款能力预测

> 本节用于学习模型选型与风险治理思路，不构成任何授信、额度或定价决策建议。实际应用必须符合适用的金融监管、隐私保护、数据授权、反歧视、审计留痕和人工审批要求。

### 先区分两个预测目标

“还款能力”不宜只用一个分数笼统表示。信用贷款实践中通常至少拆分为两个目标：

1. **违约风险**：预测借款人在未来观察期内是否逾期/违约，或给出违约概率 **PD**（Probability of Default）。本程序演示的是这一类目标。
2. **偿付能力与额度**：估计可支配现金流、可承受月供或建议额度，并受产品与风险政策的硬约束。

若业务还需要判断“何时可能首次逾期”，还可增加第三类目标：**风险随时间变化的预测**，用于贷后预警、催收优先级等场景。

### 常见算法模型

| 目标 | 常见模型 | 优点 | 适合的作用 |
| --- | --- | --- | --- |
| 是否违约 / PD | 逻辑回归 | 可解释、可审计、部署简单 | 评分卡基线、策略规则的风险输入 |
| 是否违约 / PD | LightGBM、XGBoost、CatBoost 等 GBDT | 擅长表格数据、可表达非线性和特征交互 | 作为效果增强或挑战者模型 |
| 首次逾期时间 | Cox、生存模型、AFT、生存梯度提升 | 关注风险随账龄的变化 | 贷后预警与时间窗口预测 |
| 可承受月供 / 额度 | 线性回归、Ridge/Lasso、分位数回归、GBDT 回归 | 输出连续数值 | 现金流估计、额度建议的输入 |

### 还款能力与额度不能只由模型决定

回归模型可以估计可支配现金流或可承受月供，但不应直接决定放款或额度。实际决策至少应受明确业务边界约束：

```text
建议月供 ≤ 可支配收入 × 偿债率上限
建议额度 ≤ 产品额度上限
建议额度受 PD、期限、风险等级、资金成本和既有政策共同约束
```

高风险名单、身份真实性、反欺诈、产品准入和监管限制等属于硬规则或人工审核范围，不能因为模型给出较低风险就被绕过。

### 特征示例与数据边界

在取得合法授权、遵循最小必要原则并保护个人隐私的前提下，常见的特征方向包括：

- **收入与稳定性**：收入水平、收入波动、工作年限、行业稳定性；
- **负债与偿债压力**：现有月供、负债收入比（DTI）、债务偿付比（DSR）、授信使用率；
- **信用历史**：历史逾期次数、最长逾期天数、账户年龄、多头申请频率；
- **行为与现金流**：还款记录、余额波动、收支稳定性；
- **贷款属性**：申请金额、期限、利率、预期月供；
- **风险控制信号**：身份和设备一致性等反欺诈信号。

不得将敏感个人信息、未经授权的数据或可能产生不合理歧视的信息直接作为授信依据，例如种族、宗教、健康状况等。具体字段边界应由合规、法务、数据治理和风险管理要求共同确定。

### 推荐的决策分层

更稳妥的做法不是让一个模型全权决策，而是让模型成为受约束决策链路的一部分：

```text
申请信息、征信、收入、负债、还款历史
              │
              ├── 身份真实性 / 反欺诈 / 准入规则 / 合规硬约束
              │
              ├── PD 模型：预测未来违约概率
              │
              ├── 偿付能力模型：估计现金流或可承受月供
              │
              ├── DTI/DSR、额度上限、期限和风险定价等策略约束
              │
              └── 自动决策或进入人工审核，并保留可追溯记录
```

## 本示例的边界与下一步

该程序用于理解流程，不应用于真实信用审批：

- 数据集只有 15 条人工构造样本，不具备代表性。
- 合成标签的模式过于简单，不能反映真实违约形成机制。
- 单次 80/20 切分的测试集极小，分类指标会有很大波动。
- 固定学习率、固定迭代次数和 `0.5` 阈值只为教学演示。
- 逻辑回归只表达线性关系，不能自动捕捉复杂非线性和特征交互。

在实际项目中还应考虑：

1. 收集已授权、可审计、足够大且有代表性的数据，并处理缺失值、异常值和样本偏差。
2. 使用时间外验证、交叉验证、概率校准和独立的模型验证。
3. 持续监控数据漂移、模型性能、稳定性、公平性与业务损益。
4. 建立可解释性、版本管理、审批流程、人工复核和完整审计留痕。
5. 将模型严格置于合规的准入、反欺诈、额度、定价和风险策略约束之下。
