# 算法与模型：Golang 入门示例

本项目通过一个可直接运行的 Go 程序，展示两个基础概念：

1. **算法（Algorithm）**：二分查找。
2. **模型（Model）**：多特征线性回归。

代码位于 [main.go](main.go)。二分查找的规则由程序员明确写出；线性模型的具体参数则从样本数据中训练得到。

本示例还演示了机器学习中两个关键步骤：

- 将样本划分为训练集和测试集。
- 只用测试集计算预测误差（MAE、RMSE）。

## 运行程序

需要本机安装 Go。进入项目根目录后执行：

```bash
go run main.go
```

也可以执行单元测试：

```bash
go test ./...
```

程序会先打印二分查找结果，再输出多特征模型的训练集/测试集数量、拟合公式、每条测试样本的预测结果与误差指标。数值末位可能因 Go 版本或浮点运算的微小差异而略有不同。

## 程序结构

```text
main.go
├── binarySearch       二分查找算法
├── Sample             一条有标签的机器学习样本
├── LinearModel        多特征线性模型的参数
├── Predict            使用模型预测
├── trainLinearModel   通过最小二乘法训练模型
├── solveLinearSystem  用高斯消元解线性方程组
├── splitSamples       按固定随机种子划分训练集和测试集
└── evaluate           用测试集计算 MAE 和 RMSE

main_test.go
└── 训练、预测、划分和误差计算的单元测试
```

## 第一部分：算法——二分查找

### 什么是算法

算法是**为解决问题预先定义的一系列明确步骤**。同样的输入、同样的步骤，会得到同样的输出。

程序中的 `binarySearch` 函数在一个**已排序**的整数数组中查找目标值：

```go
func binarySearch(sorted []int, target int) int
```

- `sorted`：必须是从小到大排列的数组。
- `target`：要查找的数字。
- 返回值：找到时返回下标；找不到时返回 `-1`。

Go 的数组下标从 `0` 开始：

```text
下标:  0  1  2  3  4  5  6
数据:  3  8 12 19 24 31 42
```

因此 `24` 位于下标 `4`。

### 代码逐段讲解

```go
left, right := 0, len(sorted)-1
```

`left`、`right` 表示当前搜索区间的左右边界。对 7 个元素的数组，初始搜索区间是 `[0, 6]`。

```go
for left <= right {
    middle := left + (right-left)/2
```

区间尚未为空时，计算中间元素的位置。`left + (right-left)/2` 是常见的稳妥写法，可避免大整数相加可能产生的溢出。

```go
switch {
case sorted[middle] == target:
    return middle
case sorted[middle] < target:
    left = middle + 1
default:
    right = middle - 1
}
```

- 中间值等于目标：立即找到。
- 中间值小于目标：目标只能在右半部分，丢弃左半部分。
- 中间值大于目标：目标只能在左半部分，丢弃右半部分。

查找 `24` 的过程：

| 轮次 | 搜索区间 | 中间下标 | 中间值 | 判断 | 下一步 |
| --- | --- | ---: | ---: | --- | --- |
| 1 | `[0, 6]` | 3 | 19 | `19 < 24` | 搜索 `[4, 6]` |
| 2 | `[4, 6]` | 5 | 31 | `31 > 24` | 搜索 `[4, 4]` |
| 3 | `[4, 4]` | 4 | 24 | `24 == 24` | 返回 `4` |

每一轮大约排除一半元素，因此时间复杂度是 **O(log n)**。二分查找的前提是数组有序；无序数据不能可靠地判断该保留哪一半。

## 第二部分：模型——多特征线性回归

### 什么是模型

模型表示从数据中总结出来的规律。程序不会手写“学习一小时能提高多少分”，而是将已有样本交给训练算法，计算出最能贴近样本的参数。

本示例用三个特征预测考试分数：

| 特征 | 含义 | 示例值 |
| --- | --- | --- |
| `study hours` | 学习时长 | `4.5` 小时 |
| `attendance rate` | 出勤率 | `0.88`，即 88% |
| `previous score` | 之前的成绩 | `76` 分 |

待预测的考试分数是**标签**（label）。一条训练数据由特征和标签组成：

```go
type Sample struct {
    Features []float64
    Label    float64
}
```

例如：

```go
Sample{
    Features: []float64{4.5, 0.88, 76},
    Label:    91,
}
```

将两者放进同一个 `Sample`，可以避免平行数组中“第 i 个特征和第 i 个标签错配”的问题。

### 多特征线性模型公式

一元线性回归使用：

```text
y = w × x + b
```

多特征线性回归将它扩展为：

```text
y = w₁x₁ + w₂x₂ + … + wₙxₙ + b
```

- `x₁, x₂, …, xₙ`：多个输入特征。
- `w₁, w₂, …, wₙ`：各特征对应的权重。
- `b`：偏置（bias）或截距（intercept）。
- `y`：模型预测的标签。

代码中用下面的结构保存已经训练出的模型：

```go
type LinearModel struct {
    Weights []float64
    Bias    float64
}
```

### `Predict`：用参数预测新样本

```go
func (m LinearModel) Predict(features []float64) (float64, error) {
    if len(features) != len(m.Weights) {
        return 0, fmt.Errorf("expected %d features, got %d", len(m.Weights), len(features))
    }

    prediction := m.Bias
    for i, feature := range features {
        prediction += m.Weights[i] * feature
    }
    return prediction, nil
}
```

预测时从偏置 `b` 开始，再累加每个 `weight × feature`。特征数量必须与模型训练时的数量一致；例如三特征模型不能只提供两个特征。这里返回 `error`，使调用方可以处理维度不匹配，而不是静默给出错误结果。

### `trainLinearModel`：从样本计算参数

```go
func trainLinearModel(samples []Sample) (LinearModel, error)
```

训练是根据一批带标签样本寻找权重和偏置的过程。函数首先检查：

- 样本不能为空。
- 每条样本必须至少有一个特征。
- 所有样本的特征数量必须相同。
- 对 `n` 个特征，至少需要 `n + 1` 条样本拟合 `n` 个权重和一个偏置。

### 普通最小二乘法

训练采用**普通最小二乘法**（ordinary least squares, OLS）。它选择一组参数，使所有训练样本的“预测值和真实值之差的平方和”尽量小：

```text
Σ(prediction - actual)² 尽量小
```

将全部特征写成矩阵 `X`、标签写成向量 `y`，参数写成向量 `θ`，可得到正规方程：

```text
(XᵀX)θ = Xᵀy
```

这里的 `θ` 包含偏置和全部权重。为统一处理偏置，代码为每一行数据添加一个值为 `1` 的首列：

```text
原始特征:       [学习时长, 出勤率, 之前成绩]
加入截距列后:    [1, 学习时长, 出勤率, 之前成绩]
```

这样 `θ` 的第一个值就是 `Bias`，后续值就是 `Weights`。

代码不会显式求矩阵逆，而是先累积出 `XᵀX` 和 `Xᵀy`，再调用 `solveLinearSystem` 解方程组。这比直接使用 `(XᵀX)⁻¹` 更适合作为基础实现。

### `solveLinearSystem`：高斯消元

`solveLinearSystem` 使用**高斯消元法**。它将矩阵与右侧向量拼成增广矩阵，逐列消去主对角线下方的元素，最后从最后一行开始回代得到参数。

每一列选择绝对值最大的可用元素作为主元（partial pivoting，部分主元选择），可减轻浮点除法带来的不稳定性。如果主元接近 0，说明特征无法唯一确定一组参数，函数返回 `features produce a singular matrix`。

例如，当两个特征完全重复，或者所有样本的某个特征都一样时，可能出现这种**奇异矩阵**。这说明数据没有提供足够的独立信息。

## 第三部分：训练集与测试集

### 为什么不能用训练数据评估自己

若模型既看过某些数据，又用这些数据评估好坏，它可能只是“记住”了样本，不能说明面对新数据是否可靠。这种问题称为**数据泄漏**的一种常见形式。

因此代码先调用：

```go
trainSamples, testSamples, err := splitSamples(samples, 0.8, 42)
```

- `0.8`：80% 样本训练，20% 样本测试。
- `42`：随机种子。相同的种子产生相同的打乱顺序，因此每次运行的训练集、测试集和输出都可复现。

`splitSamples` 先复制原始切片，再打乱复制品，因而不会修改调用方保存的原始样本顺序。它也会确保训练集和测试集都至少含一条样本。

流程如下：

```text
全部带标签样本
      │
      ├── 固定种子打乱
      │
      ├── 80% 训练集 ──> trainLinearModel ──> 模型参数
      │
      └── 20% 测试集 ──> Predict + evaluate ──> MAE / RMSE
```

测试集标签只在最后用于比较预测结果，不能用于训练模型参数。

## 第四部分：预测误差

`evaluate` 函数遍历测试集，针对每条样本执行 `Predict`，再将预测值与真实标签比较：

```go
errorValue := prediction - sample.Label
```

### MAE：平均绝对误差

**MAE**（Mean Absolute Error）定义为：

```text
MAE = Σ|prediction - actual| / 测试样本数
```

它回答的问题是：模型的预测平均距离真实值多少。例如，`MAE = 2.5` 可以理解为“每次预测平均相差约 2.5 分”。数值越接近 `0` 越好。

### RMSE：均方根误差

**RMSE**（Root Mean Squared Error）定义为：

```text
RMSE = √(Σ(prediction - actual)² / 测试样本数)
```

平方会更严厉地惩罚很大的误差。因此当 RMSE 远大于 MAE 时，常表示少数样本的预测误差特别大。它同样越接近 `0` 越好。

程序会输出每条测试样本的：

```text
features=..., predicted=..., actual=..., residual=...
```

其中 `residual` 是残差，即 `predicted - actual`：

- 正数：预测偏高。
- 负数：预测偏低。
- 绝对值越大：该样本误差越大。

测试集很小，只用于演示流程；不能将一次运行的 MAE/RMSE 当作真实教育场景中模型质量的可靠结论。

## 算法与模型的对比

| 维度 | 二分查找算法 | 多特征线性回归模型 |
| --- | --- | --- |
| 规则来源 | 程序员明确编写 | 训练算法根据数据计算参数 |
| 是否训练 | 不需要 | 需要 `trainLinearModel` |
| 使用时输入 | 有序数组和目标值 | 多个数值特征 |
| 输出 | 确定的下标或 `-1` | 连续数值预测 |
| 质量依据 | 输入是否满足“有序”前提 | 测试集上的 MAE、RMSE 等指标 |
| 本例实现 | `binarySearch` | `trainLinearModel`、`Predict`、`evaluate` |

机器学习并不取代算法。训练线性模型的最小二乘法、高斯消元、训练测试划分都是算法；这些算法的输出是一个模型参数集合，而模型再用这些参数预测未知样本。

## 本示例的边界与下一步

该程序用于理解流程，不应直接用于真实成绩预测：

- 数据集只有 12 条人工构造样本，不具备代表性。
- 分数还受课程质量、题目难度、睡眠和其他因素影响。
- 线性关系是一个简化假设，真实关系可能是非线性的。
- 样本很少，单次 80/20 切分的评估波动会很大。
- 正规方程在特征高度相关或量纲差异很大时，数值稳定性可能较差。

在实际项目中还应考虑：

1. 收集足够多且有代表性的数据，并处理缺失值和异常值。
2. 对特征做标准化/归一化，降低不同量纲的影响。
3. 使用交叉验证，而非依赖一次训练/测试划分。
4. 使用更稳定的 QR、SVD 等数值方法或成熟数值库。
5. 在部署前持续评估模型偏差、公平性和数据分布变化。
